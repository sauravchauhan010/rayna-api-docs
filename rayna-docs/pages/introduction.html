Introduction

This document provides technical details about the APIs — the business processes, connection specifications, and integration guidelines for developers.

Connection Properties

Communication with the system is performed through HTTPS connections. The following properties must be used:

RequestValueDescription
Request MethodPOSTAll API calls use the POST method.
Content-Typeapplication/jsonThe content type for all requests.

Request / Response

It is recommended that all booking and cancellation transactions sent through the Test / Live environment be logged and maintained by the travel agent for at least 6 months.

Go-Test / Live Process

To start testing, notify our support team via e-mail. All transactions through the test system are simply test transactions and will not be sent to suppliers.

Do not compare the products with the Live Environment. The system functionality is identical except that bookings processed in the Test environment are not sent to Suppliers. Whitelisting of the Test/Live Server IP address is essential.

Client Requirements

  • Client requests must be issued from a public, static IP address registered with the System.
  • Client requests must be made via an HTTPS POST request.
  • SSL is required.
  • All data sent and received via the interface will be encoded in UTF-8.

Development Phase

Once you receive your Access Token, you can start development. Communication consists of simple JSON message exchanges (request/response) between your application and the system. Each request must be posted via HTTPS POST.
